Why this one

The number lands exactly where it changes. Switching tabs is the only thing that alters it, so the tabs are its natural home.

Frees the whole row, and the extra numbers are useful before you click: "9 active, 5 done" is a mini dashboard in the toolbar.

Counts respect the saved view's filters and the in-place search, so each one is "what you'd get if you clicked".

Full version needs one small API addition — counts per status group for the current criteria (same shape the list already returns for groups when grouping). A-lite needs nothing: it reuses total.

Tabs get ~20px wider each; fine at this toolbar width, worth checking at 1280px.

Suggested direction

Drop the line, move the count into the status tabs (A), and turn the "Showing X of Y" note into a table footer (D). The bulk bar already covers "3 selected", so nothing on the old line is lost.

  1. Step one, no API change: A-lite — show the count on the selected status tab using the total the page already has. Remove page-head. Immediate 42px back.
  2. Step two, small API change: return counts for all five groups under the current filters, and light up every tab.
  3. Step three: fold the partial-load note into a table footer.
